# 文档层次与写作参考 / Documentation structure

## 中文

Nebula Focus 延续 Node Console 的文档偏好：中文在前，英文在后；两部分使用对应的标题和内容层次。

原参考文档是阮一峰的 [中文技术文档写作规范](https://github.com/ruanyf/document-style-guide)。Node Console 在 2026 年 6 月 12 日采用该规范调整 README，相关提交为 [d0a09d9 — Revise README wording](https://github.com/AnthemZhou/Node_Console/commit/d0a09d9)。

当前 README 采用以下结构：

1. 项目名称、简短定位、语言入口和版本信息。
2. 产品简介与主要功能。
3. 安装条件和安装步骤。
4. 日常操作与快捷键。
5. 数据保存位置和兼容范围。
6. 开发、反馈和许可证信息。

层级使用项目名、语言、章节三级标题。功能列表说明主要价值；操作表格说明怎样使用。数据边界和兼容细节单独成节，便于按需查阅。

写作参考包括：[标题](https://github.com/ruanyf/document-style-guide/blob/master/docs/title.md)、[文本](https://github.com/ruanyf/document-style-guide/blob/master/docs/text.md)、[文档体系](https://github.com/ruanyf/document-style-guide/blob/master/docs/structure.md)。采用短句、清楚的动作描述、统一的列表与中英间距。英文示例使用英文；界面或配置要求的固定名称保留原文并解释用途。

## English

Nebula Focus follows Node Console's Chinese-first, English-second layout. Both language sections use matching headings and cover the same information.

The original reference is Ruan Yifeng's [Chinese technical writing guide](https://github.com/ruanyf/document-style-guide). Node Console adopted it for its README on June 12, 2026; see [d0a09d9 — Revise README wording](https://github.com/AnthemZhou/Node_Console/commit/d0a09d9).

The README follows this order:

1. Project name, brief purpose, language navigation and version information.
2. Introduction and main features.
3. Prerequisites and installation steps.
4. Everyday operations and keyboard shortcuts.
5. Data storage and compatibility.
6. Development, feedback and license information.

Use three heading levels for the project name, language and sections. Feature lists explain value; operation tables explain usage. Keep data boundaries and compatibility details in their own sections.

References cover [headings](https://github.com/ruanyf/document-style-guide/blob/master/docs/title.md), [text](https://github.com/ruanyf/document-style-guide/blob/master/docs/text.md) and [document structure](https://github.com/ruanyf/document-style-guide/blob/master/docs/structure.md). Favor short sentences, clear actions and consistent formatting. Use English examples in the English section; retain exact interface or configuration identifiers where required and explain their role.
